# Adversarial review — v2-greenfield branch (2026-06-12)

7 finder angles → 33 deduped candidates → per-candidate verification.
**28 confirmed, 4 plausible, 1 refuted.** Ranked: security/data-loss first.

## Top findings (the ≤10 cut)

1. **[security] kernel/step.py:216 — request-snapshot effects default to `Effects(0)` → auto-Allow.**
   `policy.judge(call, spec_effects.get(call.name, Effects(0)))`: a tool absent from the request-time
   snapshot (added by mid-turn MCP reconnect) gets zero effects, every guard abstains, the chain
   falls through to Allow with no Ask, and the executor runs it from the live source. Same mechanism
   serves stale effects when an annotation flips. Fix: unknown name ⇒ full-caution effects
   (`WRITE_PATH|EXEC|EXTERNAL`), and judge with `max(snapshot, live)` caution.

2. **[security] drive/executor.py:137 — `format:"path"` containment skips nested/array paths.**
   `_contain` walks only top-level string properties; `{"files": {"type":"array","items":{"format":"path"}}}`
   passes raw escaping paths to the tool. `sensitive_path_guard` has the same top-level blindness.
   Voids DESIGN's "forgetting is impossible, including for third-party tools". Fix: recursive schema walk.

3. **[security] adapters/mcp/manager.py:106 — `readOnlyHint=true` trusted with auto-Allow + parallelism.**
   One server-controlled boolean ⇒ `READ_PATH` ⇒ no guard fires, parallel scheduling — contradicting the
   module's own docstring ("we do not trust self-description with parallelism or auto-allow").
   Fix: read-only hint may earn READ_PATH for scheduling, but keep EXTERNAL for guarding (Ask at least once per server/tool).

4. **[security] front/wiring.py:220 — redaction is a documented no-op.**
   JsonlStore supports `redactor` rewrite-before-append; nothing constructs one and no Redactor impl
   exists outside tests. `Bash: env` output with live keys is fsync'd verbatim into ~/.agent-forge/sessions.
   Fix: ship a default secret-pattern redactor in wiring.

5. **[correctness] adapters/tools/fs.py:262 — EditTool partial-overlap edits silently no-op, reported as success.**
   Phase 1.5 checks equality/containment only; partially overlapping old_strings (`abcd`/`cdef` in `abcdef`),
   or edit1's new_string manufacturing edit2's old_string, pass validation; `replace(old, new, 1)` then
   no-ops or hits the wrong occurrence while the tool reports "Replaced 1 occurrence(s)".
   Fix: re-validate each old_string against the working text at apply time; error on zero replacements.

6. **[reliability] kernel/state.py:72 + step.py:249 — duplicate tool-call ids wedge the session.**
   `batch_complete` compares counts; `pending_calls` dedupes by id — two ToolCalls sharing an id
   (adapter passes API ids through unvalidated) make `declared=2, results=1` forever; turn never finishes,
   every later submit is purely ignored. Fix: dedupe/reject duplicate ids at `_on_model`.

7. **[data-loss] adapters/jsonl_store.py:105 — torn write minus trailing newline corrupts the log.**
   `_recover` truncates only on JSON-parse failure; a complete-but-newline-less tail is kept and the next
   append (mode "a") concatenates onto the same line — replay later rejects the line; session unresumable.
   Fix: also truncate (or newline-repair) when the tail lacks `\n`.

8. **[data-loss] kernel/step.py:191 — empty compaction summary durably erases the conversation.**
   A compaction response with no TextBlocks → `summary=""` → `apply_compaction` wipes messages, and
   `if summary:` rendering treats it as absent: next request has zero context, and fold faithfully replays
   the loss. Fix: reject empty summaries (keep window, skip compaction, log it).

9. **[reliability] adapters/anthropic.py:362 — mid-stream overload classified fatal; never retried.**
   SDK raises mid-stream SSE errors with the HTTP-200 stream response → `status_code=200` ∉ `_RETRY_CODES`
   → `FatalProviderError` for a textbook-transient `overloaded_error`. Fix: classify by error type/body,
   not only status code.

10. **[reliability] drive/session.py:122 — resume never closes a crashed-open turn; session bricked.**
    After kill-9 mid-turn (or any exception escaping `run_turn` — see C2/C3 triggers below), the log folds
    to `in_turn=True` and every subsequent submit is ignored purely. Fix: on resume, if `in_turn`, step a
    synthetic `Cancelled` to close the turn (and catch-all in the driver so escapes still write TurnFinished).
